# Respostas

## 1. O que é um repositório?

Um repositório é o local onde ficam armazenados os arquivos e todo o histórico de alterações de um projeto. No GitHub, ele permite organizar o projeto e acompanhar as modificações feitas durante o desenvolvimento.

## 2. Qual a diferença entre Git e GitHub?

O Git é uma ferramenta utilizada para controlar as versões de um projeto no computador. O GitHub é uma plataforma online que permite armazenar projetos que utilizam Git, além de facilitar o compartilhamento e o trabalho em equipe.

## 3. Para que serve um commit?

O commit serve para registrar uma alteração feita no projeto. Ele funciona como um ponto de salvamento, permitindo identificar o que foi alterado e acompanhar o histórico do desenvolvimento.

## 4. Por que utilizamos branches?

As branches são utilizadas para desenvolver novas funcionalidades ou fazer alterações sem modificar diretamente a versão principal do projeto. Assim, é possível trabalhar de forma mais organizada e segura.

## 5. Qual a finalidade de um Pull Request?

O Pull Request serve para solicitar que as alterações feitas em uma branch sejam analisadas e, depois, incorporadas à branch principal. Ele também permite revisar as alterações antes da integração.

## 6. Qual a diferença entre fazer um commit e fazer um push?

O commit registra as alterações no repositório local. O push envia esses commits do computador para o repositório remoto, como o GitHub.

## 7. O que acontece quando um Pull Request é realizado?

Quando um Pull Request é realizado, as alterações de uma branch ficam disponíveis para análise. É possível verificar os arquivos modificados, revisar o código e, se estiver tudo certo, realizar o merge para a branch principal.

## 8. Qual a finalidade do merge?

O merge serve para unir as alterações de uma branch com outra. Por exemplo, depois que uma alteração é analisada em um Pull Request, o merge pode incorporar essa alteração à branch principal.

## 9. Por que não é recomendado realizar todo o desenvolvimento diretamente na main?

Porque trabalhar diretamente na main pode causar problemas na versão principal do projeto. O uso de branches permite desenvolver e testar alterações separadamente, reduzindo o risco de erros e facilitando a revisão antes de colocar as mudanças na versão principal.
